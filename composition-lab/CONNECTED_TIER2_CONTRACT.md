# Connected Tier1 / Tier2 contract

Completion and creative-lever acceptance are governed by
[PROJECT_COMPLETION_PLAN.md](PROJECT_COMPLETION_PLAN.md). Exact source reversal
and retained detector parity do not complete the Tier2 creative levers. Each
declared lever must pass its own musical, same-relation inverse, control/lock,
GP/playback and three-QA gateway before the tier can be marked complete.

Active scope: complete captured source ownership and integration of retained
musical/technique analysis. Accepted detectors and JSON/GP conversion are unchanged.
No new composition engine, artist model or performed-sound claim.

| Boundary | Authority | What is deliberately not claimed |
|---|---|---|
| T0 | Captured Songsterr metadata and track JSON | Original GP bytes or a verified performance |
| T1 | Every JSON scalar/container, exact type, presence, ordered membership and source address | Musical interpretation |
| T2 source structure | Document identities and value-free ordered membership | Musical abstraction merely from storing structure |
| T2 musical relationships | Written coattack pitches/intervals and rational note timing | A selected key, chord intention, emotional meaning or acoustic pitch |
| T2 physical positions | `pitch = tuning + capo + fret`, solved in either direction | Invented pitches for dead, percussion or unresolved notes |
| T2 technique declarations | Registered typed observations; bends/whammy normalized to semitones and fractional position | Unwritten vibrato depth/speed or a guessed slide endpoint |
| T2 source choices | Registered notation spelling, instrument settings, controls, catalog/provenance | Higher musical understanding from those choices alone |
| T2 derived views | Existing harmonic, tie, technique, dynamics and approved pedal analyses | An independent pitch authority or hidden inverse input |
| Coverage | Exactly one reconstruction owner per T1 fact; explicit unsupported inventory | A complete inverse when unknown owners remain |

## One input; no raw-note fallback

`connected_tier2.analyze(complete_T1)` receives only its immediately preceding
Tier1. Source-shaped compatibility documents exist temporarily in memory so the
accepted pure parsers/detectors can run unchanged. Higher analysis does not reopen
T0 files. The complete T1 is nested once, for evidence/inspection.

For reverse QA, `strip_lower` removes the entire T1 and all derived reports.
`reconstruct` receives source structure, registered parameters, musical equations
and ownership inventory only. It rejects extra payload keys, duplicate owners,
unknown structures, missing owners, unreachable facts and conflicting pitch/time.

Known frets are not stored again as source-choice numbers. Coattack pitch is the
single authority. The same physical equation obtains fret from pitch, tuning,
capo and string, with an exact original integer/float/negative-zero witness.
Unresolved positions retain explicit source choices rather than a guessed pitch.

Notated fractions retain their exact spelling and scalar types. Metric duration
is a musical relationship, not a substitute for the original notation. The actual
reverse function re-extracts pitch/time from its newly realized facts through the
same existing pure source projection and rejects inconsistent choices.

## Technique connection and limits

Source occurrence addresses connect retained technique output to the written
pitch/time relationships. Existing bend curves, HP candidates, slide resolution,
dynamics, ties, close-interval textures, double stops, power/extended power chords
and approved pedal support/continuation output are recomputed from the same facts.

These retained analyses are checked derived views. Reverse does not consume their
cached reports. Registered source technique declarations do have shared inverse
relationships; the complete higher-level technique interpretations are not yet
all inverse-driving abstractions. This integration must not be described as
artist-style generation or a finished higher-level musical model.

The source-field registry contains only finite observed paths/types, never song
values or musical preferences. Newly encountered fields/types require a named
owner; a generic payload codec is forbidden. Source swing declarations can be
preserved without claiming verified swing playback. Unknowns remain visible.

## Three independent acceptance gates

1. **Portability:** frozen new random capture selected before this implementation;
   run unchanged logic, retain failed attempts, no easier replacement song.
2. **Exact reversal:** audited `-I -S` worker receives only stripped parameters and
   frozen code. Source, T1, caches and checker expectations are absent. Independently
   reconcile its actual output against every raw JSON path/type/value/order.
3. **Musical abstraction:** review actual source/time links and meaningful
   contrasts—bend units, HP direction/open-string context, specified/unspecified
   slide endpoints, known/unknown dynamics, interval-group definitions and later
   pedal responses. Retained-output parity and exact recovery alone are insufficient.

Planner reviews design, midpoint defects and final evidence. Mutation checks call
actual reverse directly, including unknown-field, duplicate-authority and timing
conflicts. No listening or musical-quality result is inferred from serialization.
